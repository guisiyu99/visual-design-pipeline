# 我的 AI 辅助设计工作流

为什么 AI 生成的页面视觉质量不稳定？我认为问题之一是大家希望从 PRD 一步到位生成高质量页面，但设计其实需要**先建立标准、验证标准，再批量延展**。

## 1. 理解需求
**工具：ChatGPT / Codex**

把 PRD 交给 AI，梳理用户、业务流程、页面清单，选出代表性页面作为验证样板。

## 2. 寻找视觉参考
**工具：ChatGPT / 设计参考图库**

寻找质量高且符合产品类型的视觉参考，比较 2–3 种方向。团队可以沉淀内部参考图库。

## 3. 提取 Design Spec
**工具：ChatGPT / Codex**

从参考图里提取**形、色、质、构、字**：颜色、字体、间距、圆角、导航结构等。这是候选规范，不能直接当最终标准。

## 4. 可视化验证
**工具：Codex + Stitch / Figma**

让 Codex 结合 PRD 和 Design Spec 生成提示词，先在 Stitch/Figma 里看到页面。把截图或链接交给 ChatGPT 诊断：不合格就修改提示词，反复验证。**目的是验证规则，而不是急于开发 HTML。**

## 5. 固化 design.md
**工具：Codex + Figma MCP / Stitch**

验证通过后读取设计结果，整理正式的 `design.md`，包含字体、颜色、间距、布局、组件和状态规范。无法准确测量的值需要标注为估算。

## 6. 批量生产页面
**工具：Codex / Figma / 前端环境**

依据 PRD 和 `design.md` 继续生成产品原型、Figma 设计稿或 HTML/React 页面。持续对照样板，检查偏差。

## 7. 复盘经验
**工具：ChatGPT / Codex**

记录每次问题的原因、修改与验证结果。项目特殊规则保留在项目中，跨项目验证的经验才进入通用经验库，减少重复犯错。

---

**一句话总结：** PRD → 视觉参考 → Design Spec → 可视化验证 → design.md → 页面生产 → 经验复盘。

我把这套工作流封装成 Codex Skill，目的是让产品经理或 FDE 只需提供 PRD，AI 主动推进流程，用户在关键节点参与判断。
