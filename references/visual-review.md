# 可视化质量评审标准

评审时必须具备真实页面证据（截图、可访问链接、Figma 节点或运行预览）。

| 维度 | 检查点 |
|---|---|
| 产品适配 | PRD 核心任务、关键字段、操作路径是否存在 |
| 信息层级 | 主次清晰，标题、数值、操作易识别 |
| 视觉一致性 | 字号、颜色、间距、圆角和组件使用有规则 |
| 空间密度 | 样板和高密度状态均可读、可操作 |
| 交互反馈 | 悬停、禁用、加载、空、错、成功反馈 |
| 可访问性 | 文字对比度、键盘可达、触控尺寸等 |
| 实现可行性 | 资源、布局和组件可落地 |

**P0**：核心流程无法完成、重大内容缺失、关键控件不可用；必须修复。

**P1**：明显视觉不一致、信息层级混乱、重要状态缺失；优先修复。

**P2**：局部视觉细节与非关键优化；可跟踪。

每条问题记录：位置 → 症状 → 原因假设 → 修改建议 → 复验方法。只有用户确认且核心场景通过才可正式固化 design.md。
